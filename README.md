## Сеть по продаже электроники
#Веб-приложение на Django для управления иерархической сетью поставщиков электроники (заводы, розничные сети, индивидуальные предприниматели). Проект включает административную панель с расширенными возможностями и REST API на базе Django REST Framework (DRF).

# Функциональные возможности
Модель данных
Три уровня иерархии: завод (уровень 0), розничная сеть (уровень 1), индивидуальный предприниматель (уровень 2).

Каждое звено сети может иметь только одного поставщика (ссылку на предыдущий объект сети).

Автоматический расчёт уровня иерархии при сохранении.

Связь с контактными данными (email, страна, город, улица, номер дома).

Возможность добавления продуктов (название, модель, дата выхода на рынок).

Фиксация задолженности перед поставщиком (с точностью до копеек) и времени создания записи.

Административная панель
Регистрация моделей для удобного управления.

Inline-форма для контактных данных прямо на странице узла сети.

Фильтрация объектов по городу.

Кастомное действие для очистки задолженности у выбранных объектов.

Кликабельная ссылка на поставщика.

# REST API (DRF)
Полный CRUD для модели поставщика (узла сети).

Запрет на обновление поля «Задолженность перед поставщиком» через API (обновление задолженности невозможно через методы PUT/PATCH).

Фильтрация списка узлов по стране (параметр ?contact__country=<название>).

Права доступа: только активные сотрудники (is_active=True и is_staff=True) имеют доступ к API.

Установка и запуск
Клонируйте репозиторий:

bash
git clone https://github.com/yourusername/electronics-network.git
cd electronics-network
Создайте и активируйте виртуальное окружение:

bash
python -m venv .venv
source .venv/bin/activate  # для Linux/Mac
.venv\Scripts\activate     # для Windows
Установите зависимости:

bash
pip install -r requirements.txt
Настройте базу данных в файле electro_network/settings.py (по умолчанию используется SQLite). Для PostgreSQL пример конфигурации:

python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': 'mydb',
        'USER': 'myuser',
        'PASSWORD': 'mypassword',
        'HOST': 'localhost',
        'PORT': '5432',
    }
}
Примените миграции:

bash
python manage.py makemigrations
python manage.py migrate
Создайте суперпользователя (для доступа к админке и API):

bash
python manage.py createsuperuser
Запустите сервер разработки:

bash
python manage.py runserver
Использование
Административная панель
Перейдите по адресу http://127.0.0.1:8000/admin/ и войдите под суперпользователем.

Управляйте узлами сети, контактами, продуктами.

На странице списка узлов используйте фильтр по городу и действие «Очистить задолженность».

API
API доступно по адресу http://127.0.0.1:8000/api/. Все эндпоинты требуют аутентификации (только активные сотрудники).

Эндпоинты
GET /api/nodes/ — список всех узлов (с возможностью фильтрации по ?contact__country=Россия).

POST /api/nodes/ — создание нового узла (в теле запроса передаются данные узла, контакта и список ID продуктов).

GET /api/nodes/{id}/ — детальная информация об узле.

PUT /api/nodes/{id}/ — полное обновление узла (без возможности менять задолженность).

PATCH /api/nodes/{id}/ — частичное обновление узла (задолженность игнорируется).

DELETE /api/nodes/{id}/ — удаление узла.

Пример создания узла (POST /api/nodes/)
json
{
    "name": "Завод Электроника",
    "contact": {
        "email": "factory@example.com",
        "country": "Россия",
        "city": "Москва",
        "street": "Ленина",
        "house_number": "10"
    },
    "products": [1, 2],
    "supplier": null,
    "debt": 0.00
}
Пример обновления (PUT /api/nodes/1/) — поле debt игнорируется
json
{
    "name": "Обновлённое название",
    "contact": {
        "email": "new@example.com",
        "country": "Россия",
        "city": "Санкт-Петербург",
        "street": "Невский",
        "house_number": "5"
    },
    "products": [1],
    "supplier": 2
}
Фильтрация по стране
text
GET /api/nodes/?contact__country=Россия
Особенности реализации
Уровень иерархии вычисляется автоматически на основе поставщика: если у узла нет поставщика — уровень 0 (завод), иначе уровень = уровень поставщика + 1 (но не выше 2).

В админке реализован inline для контактов, что позволяет редактировать контактные данные прямо при редактировании узла.

В API поле debt доступно только для чтения (при создании его можно указать, но при обновлении оно не изменяется).

Права доступа настроены через кастомный класс IsActiveStaff, допускающий только активных сотрудников.
